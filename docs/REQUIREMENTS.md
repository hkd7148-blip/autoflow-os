# Функциональные требования AUTOFLOW OS

## 1. Общие сведения

### 1.1 Назначение системы

AUTOFLOW OS — интеллектуальная система управления грузовым автосервисом, предназначенная для автоматизации процессов приёма клиентов, управления заказами, складского учёта и AI-диагностики.

### 1.2 Целевая аудитория

| Роль | Описание | Количество |
|------|----------|------------|
| Клиент | Владельцы/водители грузовых ТС | ~200 |
| Менеджер | Сотрудники приёмки и работы с клиентами | 2-4 |
| Механик | Специалисты по ремонту | 4-8 |
| Руководитель | Директор, управляющий | 1-2 |
| Администратор | IT-специалист | 1 |

### 1.3 Границы системы

**Входит в систему:**
- Telegram-бот для всех категорий пользователей
- REST API для интеграций
- Интеграция с 1С:Предприятие
- AI-модуль диагностики

**Не входит в систему:**
- Бухгалтерский учёт (ведётся в 1С)
- Телефония (отдельная система)
- Видеонаблюдение

## 2. Функциональные требования

### 2.1 Модуль RECEPTION (Приём клиентов)

#### FR-REC-001: Приветствие и идентификация

| Параметр | Значение |
|----------|----------|
| Приоритет | Высокий |
| Статус | Реализовано |

**Описание:** Система должна приветствовать пользователя при первом обращении и определять, является ли он существующим клиентом.

**Сценарий:**
1. Пользователь отправляет команду /start
2. Система проверяет telegram_id в базе данных
3. Если найден — приветствует по имени
4. Если не найден — предлагает зарегистрироваться

**Критерии приёмки:**
- Время ответа < 2 секунд
- Корректное определение существующих клиентов
- Сохранение telegram_id для новых пользователей

---

#### FR-REC-002: Сбор информации о проблеме

| Параметр | Значение |
|----------|----------|
| Приоритет | Высокий |
| Статус | Реализовано |

**Описание:** Система должна собирать информацию о транспортном средстве и проблеме через диалог.

**Собираемые данные:**
- Марка ТС (выбор из списка)
- Модель ТС (текстовый ввод)
- Описание проблемы (текстовый ввод)
- Контактный телефон

**Критерии приёмки:**
- Валидация введённых данных
- Возможность вернуться на предыдущий шаг
- Сохранение состояния при разрыве связи

---

#### FR-REC-003: Выбор времени визита

| Параметр | Значение |
|----------|----------|
| Приоритет | Высокий |
| Статус | Реализовано |

**Описание:** Система должна предлагать свободные слоты для записи.

**Требования:**
- Отображение слотов на 3 дня вперёд
- Исключение выходных дней
- Учёт рабочего времени (9:00-18:00)
- Синхронизация с 1С

**Критерии приёмки:**
- Актуальность слотов в реальном времени
- Невозможность записи в занятый слот
- Подтверждение выбранного времени

---

#### FR-REC-004: Создание заказ-наряда

| Параметр | Значение |
|----------|----------|
| Приоритет | Высокий |
| Статус | Реализовано |

**Описание:** После подтверждения записи система создаёт заказ-наряд.

**Требования:**

**Критерии приёмки:**
- Заказ создаётся в обеих системах
- Клиент получает номер заказа
- SMS доставляется в течение 1 минуты

## 4. Ограничения

### 4.1 Технические ограничения

- Telegram API: 30 сообщений в секунду
- OpenAI API: зависит от тарифа
- 1С: зависит от сервера клиента

### 4.2 Бизнес-ограничения

- Рабочее время: 09:00-18:00 (для уведомлений)
- Выходные: воскресенье
- Максимум записей в день: 20
